What you need

  • A Raspberry Pi Pico, Pico W, Pico 2 or Pico 2 W with MicroPython on it.
  • A USB cable that carries data. Some cables only carry power; they will charge a phone, but your computer won't see the Pico.
  • Chrome, Edge, or Firefox 151 or later, on a desktop or laptop computer.

Putting MicroPython on a Pico

  1. Download the MicroPython .uf2 file for your board from micropython.org. Each board (Pico, Pico W, Pico 2, Pico 2 W) has its own file.
  2. Hold down the BOOTSEL button on the Pico while you plug it in. A drive called RPI-RP2 (or RP2350 on a Pico 2) appears on your computer.
  3. Copy the .uf2 file onto that drive. The drive disappears and the Pico restarts, running MicroPython.

This replaces the firmware the Pico was running before.

Connecting

Click Connect and choose your Pico from the list. The list only shows Raspberry Pi boards. The first time, your browser asks whether this site may use your serial ports; say yes. Once you're connected, the files on the Pico appear on the left.

After the first time, Pipette reconnects to the same Pico without asking. To choose a different board, hold Shift while you click Connect.

The dot beside the button shows whether you're connected: filled in green when you are, hollow when you aren't.

While you're connected, Pipette holds on to the Pico's USB connection, and no other program can use it. When you've finished, click Disconnect to let it go, for example so that Thonny or another tab can use the Pico. If a program is still running, Disconnect stops it first.

Running and stopping

Run sends the program in the editor to the Pico and runs it. Its output appears under Output as it arrives. Stop interrupts a program that is still running, such as one with a while True: loop.

While a program is running, a Type to your program box appears under its output. If your program uses input(), type your answer there and press Enter. The Pico shows what you typed in the output. You can type before the program asks; it reads your line when it gets to input(). The same box appears under the REPL when a line you typed there is running.

Each run starts afresh: variables from earlier runs are cleared, but files on the Pico are kept. Run always uses what's in the editor, not a file saved on the Pico.

Tips

  • The Tab key indents by four spaces.
  • The on-board LED is Pin("LED", Pin.OUT) on every kind of Pico.

When something goes wrong

If your program stops with an error, Pipette shows you where:

  • the line's number turns red and the line is selected in the editor;
  • a message such as Line 7: NameError: name 'leed' isn't defined appears below the output. Click the line number to jump back to it;
  • the full message from MicroPython (the traceback) is shown underneath.

If the error happens inside one of your functions, the line inside the function is the one marked. Errors inside libraries are traced back to the line of your program that called them. When you press Stop, the line the program had reached is marked in the same way.

The REPL

The REPL box under the output lets you type Python and run it on the Pico straight away, a line at a time. Type an expression, such as 2 ** 10, and press Enter to see its value.

  • The REPL shares variables with the program you last ran, so after Run or Stop you can look at them, change them, or call your functions. The Variables table updates after each line.
  • After a line ending in :, or with a bracket still open, Enter starts a new line (indented for you). Press Enter on an empty line to run the whole block. Shift+Enter always starts a new line.
  • ↑ and ↓ bring back earlier lines. Stop interrupts a line that's still running.
  • Running a program starts afresh, clearing the REPL's variables too.

Variables

When your program finishes, fails or is stopped, the Variables table shows the variables it left behind, with their types and values. After pressing Stop in a loop, for example, you can see how far the loop had got.

  • Only variables at the top level of your program are shown, not those inside functions.
  • Modules, functions and classes are left out, and long values are shortened.

Files

On your computer

Open… loads a file into the editor. Save to computer saves the editor using the name in the box beside it. In Chrome and Edge it saves back to the file you opened; in other browsers it downloads a copy.

On the Pico

  • Click a file in the Pico files panel to open it in the editor. Click a folder to go into it, and .. to come back.
  • Save to Pico saves the editor into the folder shown, using the name in the box.
  • Save as main.py saves it as /main.py. The Pico runs main.py whenever it powers up, so your program will run on its own, even from a phone charger or battery. Connecting with Pipette stops it again.
  • ✕ (shown when you point at a file) deletes it, after asking. This can't be undone. Folders must be empty before they can be deleted.
  • New folder creates a folder, and ↻ refreshes the list.

Pipette marks unsaved changes and asks before replacing them.

Packages

Packages add extra modules, such as drivers for displays and sensors. Type a name in Install a package and click Install:

  • a name from micropython-lib, such as ssd1306;
  • a GitHub repository, such as github:org/repo (also gitlab: and codeberg:);
  • or the web address of a package.json, .py or .mpy file.

Pipette installs the package and anything it depends on into the Pico's /lib folder. Your browser does the downloading, so the Pico doesn't need Wi-Fi. Then use it in your program:

import ssd1306

Troubleshooting

The connection checker tests each step and tells you what's wrong.

The list of ports is empty

  • Another browser tab or program (such as Thonny) may be using the Pico. Close it, then unplug the Pico and plug it back in.
  • The cable may only carry power. Try another one.
  • The Pico may not have MicroPython on it, or may be in BOOTSEL mode (showing up as a drive). See Putting MicroPython on a Pico.

The Pico is listed but won't connect

  • Close any other tab or program using it, then unplug it and plug it back in.
  • On Linux, your user may need permission to use serial ports. Run this, then log out and back in: 
    sudo usermod -aG dialout $USER

Connected, but programs don't run

The board may be running something other than MicroPython. The connection checker will tell you; if so, put MicroPython on it.

"Pico disconnected"

The Pico was unplugged or restarted. Plug it back in and click Connect again.

Privacy

Pico Pipette runs entirely in your browser and has no server of its own. Your programs and files go only between your browser and your Pico. The only other connections are the package downloads you ask for, from micropython.org, GitHub or the address you type.
